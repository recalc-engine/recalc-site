Two bad options for Excel's answer at scale

Spreadsheets run finance. Models get priced, trades get checked, disclosures get tied out, and customer workbooks get ingested — all in .xlsx, all expected to compute exactly the way Excel computes them. When you need those numbers on a server, at volume, without a human clicking around a workbook, you pick your poison.

Trusted, unscalable

Run real Excel on Windows

A farm of licensed Excel instances driven by automation, babysat by an ops team. Slow, expensive, fragile; it doesn't fit in a container or a CI pipeline, and it's a licensing and reliability headache nobody wants to own. But it's the only thing you trust, because it is Excel.

Fast, quietly wrong

Use an open-source calc library

Fast, embeddable, free — and quietly wrong. These engines reimplement a slice of Excel's behavior and diverge in the corners: a date rolls one day off, an error type is swapped, a lookup returns 0 where Excel returns #N/A. Worst of all, they don't tell you when they've diverged. You find out downstream, when the number is already in a report.

There's never been a third option: something that computes like Excel and tells you plainly about the moments it can't.

Exactly Excel — or loudly flagged. Never a silent wrong answer.

Recalc makes one promise, and it's the one that matters: every cell is either Excel's result to the documented tolerance, or it is explicitly flagged as unsupported. When Recalc hits a function or a feature it can't reproduce faithfully, it returns a distinguishable #UNSUPPORTED! for that cell and records it in a workbook-level fidelity report. Guessing a plausible value is forbidden by design — nothing is approximated behind your back.

A 99.99% engine that silently lies on the other 0.01% is worse than a 98% engine that tells you precisely which cells it couldn't do. If you have to defend a number — to an auditor, a regulator, a risk committee, or a customer — reliability isn't "usually right." Reliability is knowing exactly when not to trust it.

A wrong number you can see is a footnote. A wrong number you can't see is a liability. Recalc is built so you never ship the second kind.

A measured number, not an adjective

"Excel-faithful" means measured agreement with Excel's own computed results on a public corpus. Text, logical, and error values match exactly; floating-point results match to a documented, published tolerance. We show you the number and the method.

Distinguishable failures, per cell

Unsupported cells are typed and reportable, not silently coerced. You can gate a pipeline on them, alert on them, or reconcile them by hand — because you know exactly which cells they are.

A tolerance you can read

Where floating-point results can differ, the allowed difference is written down, with the rationale. Nothing is fuzzy that we didn't decide, on purpose, to make fuzzy.

Open. Graph. Recalculate. Report.

01 Open the workbook

Recalc parses the .xlsx / .xlsm container directly — shared strings, defined names, tables, number formats, the 1900/1904 date system, calc settings — with hardened limits against malformed and zip-bomb inputs. No Excel, no COM, no rendering.

02 Rebuild the graph

It parses every formula — A1 and R1C1, 3-D refs, structured references, array literals, LET/LAMBDA — and builds the precedent/dependent graph, with cycle detection and iterative-calc support, tracking volatile functions the way Excel does.

03 Recalculate

It evaluates in dependency order and reproduces Excel's actual behavior — the same values, the same error types, the same edge-case quirks — to a documented tolerance, using the same coercion rules Excel applies. Anything it can't reproduce faithfully becomes a distinguishable #UNSUPPORTED!, never a guess.

04 Report

You get the computed workbook back plus a fidelity report: what matched, what was declined, and why — the artifact you hand to whoever has to trust the number.

Recalc is a calculation engine, on purpose. It doesn't render, lay out, or draw charts; it doesn't execute VBA (it reads macros only to trace dependencies); and v1 writes computed values back into the original file without rewriting everything else. It does one hard thing and tells the truth about it.

The engine is open source. Own it, run it anywhere.

Recalc's calculation core is a free, Apache-2.0 library — the same engine that scores on Sheetmark, with no crippled "community edition" and no accuracy held back for the paid tier. It's a headless Rust engine with thin, versioned bindings, so you can embed Excel-faithful recalculation directly in your stack.

The core runs on a minimal, individually-approved and exactly-pinned dependency set and takes no network or filesystem access from a formula — WEBSERVICE, RTD, and STOCKHISTORY are blocked by default, RAND is seedable, and the clock is injectable, so a recalculation is deterministic and reproducible by construction.

Questions

How accurate is it, really?

On the cells it computes, Recalc matched Excel's stored results on 98.637% of the 4,533,056 cells it attempted — 79.98% of a 5,667,851-cell public corpus — at a documented 15-significant-figure tolerance; 97.497% bit-exact with no tolerance at all. Genuine disagreements: 61,801 cells, 1.09% of the whole corpus, and a meaningful share of even those is Excel disagreeing with its own stored values, not Recalc's math. Every cell it can't compute faithfully — 20.02% of this corpus, 86.90% of it referencing other workbooks we weren't given — is declined loudly rather than guessed, so you always know exactly which cells to trust. Full method, funnel, and per-function breakdown: Sheetmark.

Why is the "coverage-inclusive" number lower than the engine number?

Because it counts every declined cell as a miss — and 86.90% of those declines reference other workbooks we weren't given (external links). Recalc correctly refuses to fabricate those: no network, no filesystem from a formula. That's a refusal over missing inputs, not a calculation error. The engine number is quality; the coverage-inclusive number is quality × coverage, bounded by what the corpus asks of the engine's declared scope.

Will it ever give me a wrong number without telling me?

That's the one thing the design forbids. Every cell is either exactly Excel's result to the documented tolerance, or a distinguishable #UNSUPPORTED! in the fidelity report. Guessing a plausible value is not allowed anywhere in the engine.

Is this legal? Did you reverse-engineer Excel or copy code?

No copied code. Recalc is a clean-room implementation: behavior is observed by running a pinned Excel build as an oracle and matching its outputs, never by reading a competing spreadsheet's source.

Do I need Excel or Windows to run it?

No. Recalc is headless and self-contained — no Excel install, no Windows, no GUI automation. That's the point.

What's open source vs. paid?

The calculation engine and its bindings (Python / Node / WASM / Rust) are free and Apache-2.0. xl-server — the hosted or on-prem batch API, the content-hash cache, and the fidelity certificate — is the commercial product.
